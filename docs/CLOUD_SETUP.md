# เปิดใช้ฐานข้อมูลกลาง ReadTech Companion

ส่วนเว็บมีบัญชีครู โปรไฟล์ผู้เรียน การฝึกต่อจากผลกลาง และรายงานแยกรายคนแล้ว ต้องติดตั้งฐานข้อมูลในบัญชี Supabase ของผู้ดูแลก่อนจึงใช้โหมดกลางได้ โหมดทดลองและผลเดิมใน IndexedDB ยังใช้ได้โดยไม่เชื่อมต่อ

## สำหรับครูที่ใช้เว็บ ReadUP ปัจจุบัน

เว็บตั้งค่ากลางให้เชื่อมกับโปรเจกต์ ReadUP แล้ว ครูไม่ต้องกรอก Project URL หรือ Publishable key ให้เปิด **หน้าเข้าสู่ระบบ → เลือกครู → อีเมลและรหัสผ่าน** ด้วยอีเมลและรหัสผ่านที่ผู้ดูแลเพิ่มไว้ จากนั้นครูลงทะเบียนผู้เรียนและส่งรหัสเข้าเรียนพร้อมรหัสผ่านให้ นักเรียนเปิด **หน้าเข้าสู่ระบบ → เลือกนักเรียน** แล้วฝึกเองได้พร้อมกันหลายเครื่อง ผู้ดูแลเปิดสิทธิ์ครูใน Supabase ครูดูเฉพาะผู้เรียนของตน และนักเรียนเห็นเฉพาะผลของตน

ค่าการเชื่อมต่อถูกจำไว้ในเบราว์เซอร์เพื่อใช้เมื่อเรียกไฟล์ตั้งค่ากลางไม่ได้ การเปลี่ยนเครื่องไม่ต้องกรอกค่าเหล่านี้ใหม่ ขั้นตอนด้านล่างสำหรับผู้ดูแลติดตั้งสำเนาเว็บหรือย้ายโปรเจกต์

## 1. สร้างโปรเจกต์และตาราง

1. เข้า https://supabase.com/dashboard สร้างโปรเจกต์ เลือกแผน Free สำหรับทดลอง
2. เปิด SQL Editor แล้วรันไฟล์ [`supabase/migrations/202610060001_readtech_cloud.sql`](../supabase/migrations/202610060001_readtech_cloud.sql) ทั้งไฟล์ **ครั้งเดียว**
3. รัน migration ที่เหลือใน `supabase/migrations` ตามชื่อไฟล์เรียงจากเก่าไปใหม่ รวม `*_readtech_student_registration.sql` และ `*_readtech_teacher_reports_and_profile_edit.sql` แล้ว deploy Edge Function `supabase/functions/readtech-student-accounts` โดยเปิด `verify_jwt = true` ไว้ ฟังก์ชันอ่าน `SUPABASE_URL` และ `SUPABASE_SERVICE_ROLE_KEY` จาก environment ฝั่ง server เท่านั้น
4. ตารางที่ได้: `readtech_teachers`, `readtech_students`, `readtech_sessions`
5. ตารางผู้เรียนและรอบฝึกเปิด RLS ครูอ่านได้เฉพาะข้อมูลของตน ผู้ไม่เข้าสู่ระบบอ่านหรือเขียนไม่ได้ ผู้สมัครบัญชีใหม่ไม่ได้สิทธิ์ครูอัตโนมัติ

## 2. เพิ่มบัญชีครูโดยผู้ดูแล

1. ใน Authentication → Users เพิ่มผู้ใช้ด้วยอีเมลและรหัสผ่านที่ครูใช้เอง
2. ใช้ User ID ของผู้ใช้นั้นเพิ่มสิทธิ์ใน SQL Editor เช่น:

```sql
insert into public.readtech_teachers (id, display_name)
values ('ใส่-USER-UUID-จาก-Authentication', 'ครูผู้ดูแล');
```

ให้ผู้ดูแลเปลี่ยนข้อความตัวอย่างเป็น UUID จริงก่อนรัน ไม่เปิดให้บัญชีทั่วไปเพิ่มสิทธิ์ตนเอง

3. ตั้ง Authentication → URL Configuration:
   - Site URL: `https://ictcs52.github.io/ReadUP/`
   - Redirect URLs: `https://ictcs52.github.io/ReadUP/`
4. หากใช้การส่งลิงก์เปลี่ยนรหัสผ่าน ให้ตั้งค่าอีเมล/SMTP ตามคำแนะนำของ Supabase และทดสอบการรับอีเมลจริง

## 3. เชื่อมเว็บกับโปรเจกต์

ใช้ **Project URL** และ **Publishable key** จาก Project Settings → API เท่านั้น ถ้าเป็นโปรเจกต์เก่าใช้ `anon` key ได้ **ไม่ใช้ Secret/service_role key หรือรหัสผ่านฐานข้อมูลในเว็บ/GitHub**

เลือกวิธีใดวิธีหนึ่ง:

- ตั้งค่ากลางสำหรับทุกเครื่อง: แก้ `public/cloud-config.json` แล้ว deploy เช่น:

```json
{
  "url": "https://YOUR_PROJECT.supabase.co",
  "publishableKey": "sb_publishable_YOUR_PUBLIC_KEY"
}
```

- ทดลองบนเครื่องเดียว: เปิดเว็บ → **ผู้เรียน → ตั้งค่าฐานข้อมูลสำหรับผู้ดูแล** แล้วกรอกค่าข้างต้น การตั้งค่านี้เก็บเฉพาะเบราว์เซอร์นั้น
- พัฒนาในเครื่อง: ใช้ `.env.example` สร้าง `.env.local` และกำหนด `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`

คีย์สาธารณะไม่ใช่สิทธิ์ผู้ดูแล ความเป็นส่วนตัวของข้อมูลเกิดจากบัญชีครูและ RLS ใน SQL migration ต้องติดตั้งทั้งสองส่วนก่อนใช้เก็บข้อมูลจริง

## 4. ครูลงทะเบียน นักเรียนเข้าเรียนเอง

1. ครูเปิด **หน้าเข้าสู่ระบบ → เลือกครู → อีเมลและรหัสผ่าน** ด้วยอีเมลและรหัสผ่าน
2. **เพิ่มผู้เรียน**: กรอกเลขประจำตัว **4 หลัก** เช่น `0123`, **ชื่อ–สกุล** และ **ชั้น** จากตัวเลือก `ป.1`–`ป.6` ระบบใช้เลขประจำตัวเป็นชื่อผู้ใช้ และสร้างรหัสผ่าน **`RT-0123`** ไม่ต้องมีอีเมลนักเรียน
3. กด **คัดลอกรหัสให้ผู้เรียน** หรือจดส่งให้เด็ก รหัสผ่านแสดงเฉพาะหลังสร้าง/ออกรหัสใหม่ ไม่เก็บเป็นข้อความธรรมดาในตารางผู้เรียน
4. ผู้เรียนเดิมกด **สร้างบัญชีเข้าเรียน** ใต้ชื่อ ผลเดิมและรหัสประจำตัวยังคงเดิม
5. นักเรียนเปิดเว็บ → **หน้าเข้าสู่ระบบ → เลือกนักเรียน** → กรอกรหัสเข้าเรียนและรหัสผ่าน → **เข้าสู่ระบบ** นักเรียนแต่ละคนใช้เครื่องแยกกันพร้อมกันได้ ครูไม่ต้องล็อกอินหรือเลือกชื่อบนเครื่องของเด็ก
6. ครูกด **ผู้เรียน → ผู้เรียนของฉัน → ดูผล** เพื่อเปิดรายงานของคนนั้นโดยตรง ครูดูผลและเพิ่มข้อสังเกตได้ แต่ทำแบบฝึกหรือแก้คำตอบแทนนักเรียนไม่ได้ ตัวอย่างบทเรียนในพื้นที่ทดลองของครูแยกจากผลผู้เรียน
7. ลืมรหัสผ่าน: ครูกด **ออกรหัสผ่านใหม่/คืนรหัสผ่านเริ่มต้น** รหัสเข้าเรียนเดิมยังใช้ได้ แต่รหัสผ่านเดิมใช้เข้าสู่ระบบใหม่ไม่ได้ การเปลี่ยนรหัสผ่านไม่ได้รับรองว่าทุก access token เดิมหมดอายุทันที
8. **พักบัญชี / เปิดบัญชี** ปิดหรือเปิดสิทธิ์อ่านข้อมูลและส่งผล ระบบ RLS/RPC ตรวจสถานะทุกครั้ง รวมถึงคำขอจาก session เดิมที่ยังไม่หมดอายุ
9. ผลส่งอัตโนมัติประมาณทุก 5 วินาทีเมื่อกิจกรรมเปลี่ยน ก่อนเปลี่ยนเครื่องหรือออกจากระบบให้ตรวจว่าไม่มีผลรอส่ง ผลที่ส่งสำเร็จยังอยู่ในฐานข้อมูล การออกจากระบบล้างสำเนาของบัญชีนั้นในเครื่อง
10. **โหลดผลล่าสุด** จะขอยืนยันก่อนแทนที่ฉบับในเครื่องที่รอส่ง ให้ส่งออก CSV ก่อนหากต้องการเก็บทั้งสองฉบับ

เลขประจำตัว 4 หลักเป็นชื่อผู้ใช้จริง จึงต้องไม่ซ้ำกับบัญชีผู้เรียนอื่นในระบบ เก็บเป็นข้อความเพื่อรักษาเลขศูนย์นำหน้า รหัสผ่านเริ่มต้นและการคืนรหัสผ่านสำหรับบัญชีใหม่คือ `RT-` ตามด้วยเลขประจำตัว บัญชีเดิมที่ใช้รหัสเข้าเรียน 10 หลักยังเข้าสู่ระบบและใช้ผลเดิมได้

ระบบตรวจ revision ของแต่ละรอบ ถ้าสองเครื่องแก้รอบเดียวกัน ฉบับเก่าจะไม่เขียนทับฉบับใหม่ เก็บฉบับในเครื่องไว้ให้ส่งออก CSV และตัดสินใจใช้ผลกลาง

ผลทดลองเดิมไม่ย้ายเข้าผู้เรียนคนใหม่อัตโนมัติ เพราะยังไม่ทราบว่าผลเป็นของใคร ให้ส่งออก CSV จากโหมดทดลองเก็บก่อน

## ขอบเขต

- นักเรียนมีบัญชีส่วนตัว ใช้เลขประจำตัวและรหัสผ่านที่ครูให้เพื่อเข้าเรียนเอง ผลฝึกแยกรายคน
- รายงานแยกตามผู้เรียน มีเวลาฝึก ตัวช่วย ผลรายข้อ และข้อสังเกต คะแนนเกมแยกจากการประเมินอ่านจริง
- ยังไม่มี Pre-test/Post-test ครบ 5 ด้าน การบันทึกเสียงนักเรียน การแชร์ผู้เรียนระหว่างครู หรือแบบฝึก LEVEL 2–6
- การตั้งค่าตัวหนังสือ/เสียงเป็นค่าของเครื่องและพื้นที่ผู้เรียนนี้ ผลกิจกรรมเป็นข้อมูลที่ซิงก์กลาง
- แผน Free ต้องมีแผนสำรองข้อมูลแยก ดูเงื่อนไขปัจจุบันที่ https://supabase.com/pricing

## ทดสอบก่อนใช้งานจริง

ทดสอบด้วยข้อมูลจำลอง: ครู A/B มองไม่เห็นข้อมูลกัน, บัญชีที่ไม่ได้รับสิทธิ์ถูกปฏิเสธ, เปิดต่ออีกเครื่อง, ตัดอินเทอร์เน็ตแล้วกลับมา, ส่งออก CSV, และกรณีแก้รอบเดียวกันจากสองเครื่อง

การทดสอบใน repository ใช้ PostgreSQL ฝังตัวสำหรับ SQL/RLS และ mock API สำหรับหน้าจอ ไม่ถือว่าได้เชื่อมต่อ/ทดสอบกับโปรเจกต์ Supabase จริงจนกว่าจะตั้งค่าและทดสอบครบข้างต้น

## สิทธิ์บัญชีนักเรียน

- ครูที่มี `active = true` เท่านั้นเรียกฟังก์ชันสร้าง/เปลี่ยนบัญชีได้ ฟังก์ชันตรวจตัวตนผ่าน Auth และตรวจ `teacher_id` ก่อนใช้ Admin API
- `auth_user_id`, `login_id` และ `login_enabled` เปลี่ยนจาก browser Data API ไม่ได้
- นักเรียนไม่มีสิทธิ์เพิ่มผู้เรียน เปิดสิทธิ์ครู หรือแก้บันทึกประเมินของครู RPC เก็บบันทึกครูเดิมไว้เมื่อรับผลจากเด็ก
- Email ภายใน `student-<loginId>@students.readup.invalid` ใช้ผูกกับ Supabase Auth เท่านั้น ไม่ต้องมี mailbox และไม่ส่งอีเมลให้ผู้เรียน
- ไม่มี service key ใน GitHub หรือหน้าเว็บ การสมัคร Auth เองไม่ทำให้มีข้อมูลผู้เรียนหรือสิทธิ์ครู
- การทดสอบประกอบด้วย PostgreSQL/RLS ในเครื่อง, Edge Function ผ่าน SDK จริงกับ HTTP จำลอง, และ browser หลายเครื่อง ตรวจ schema/grants และการปฏิเสธ anonymous ในระบบจริงแล้ว ยังไม่ได้สร้างบัญชีทดสอบบน production

## หน้าที่แสดงตามสถานะเข้าสู่ระบบ

| หน้า | ก่อนเข้าสู่ระบบ | นักเรียน | ครู |
|---|---|---|---|
| เข้าสู่ระบบ (แบบฟอร์มเดียว เลือกครู/นักเรียน) | แสดงเป็นหน้าแรก | เมื่อออกจากระบบ | เมื่อออกจากระบบ |
| ข้อมูลแนะนำ ReadTech | เปิดได้ | เปิดได้ | เปิดได้ |
| หน้าหลัก บทเรียน รางวัล และปรับการใช้งาน | ไม่แสดง | ผลและพื้นที่ของตน | ดูรายงานของผู้เรียนที่เลือก ทดลองบทเรียนได้เฉพาะพื้นที่ครู |
| บัญชีของฉัน | ไม่แสดง | บัญชีนักเรียนของตน | บัญชีครูของตน |
| จัดการผู้เรียนและออกบัญชี | ไม่แสดง | ไม่มีสิทธิ์ | ผู้เรียนในความดูแลของตน |
| รายงาน/บันทึกประเมินสำหรับครู | ไม่แสดง | ไม่มีสิทธิ์ | เปิดหน้าได้ แล้วเลือกผู้เรียนในรายงาน |

เมื่อออกจากระบบ หรือไม่สามารถยืนยันสิทธิ์บัญชี ระบบกลับสู่หน้าเข้าสู่ระบบโดยไม่แสดงพื้นที่ส่วนตัว ผลทดลองในเครื่องเก็บไว้แต่ไม่แสดงให้ผู้ที่ยังไม่เข้าสู่ระบบ การคืน session เดิมต้องตรวจบัญชีก่อนเปิดหน้าใช้งาน ไม่ต้องกรอก Project URL/Publishable key ใหม่

## แก้ไขข้อมูลผู้เรียน

เปิด **ผู้เรียน → จัดการ → แก้ไขข้อมูล** เพื่อแก้เลขประจำตัว ชื่อ–สกุล และชั้น ระบบคง ID ของผู้เรียนและผลฝึกเดิมไว้ หากเปลี่ยนเลขประจำตัวจะเปลี่ยนชื่อผู้ใช้ Auth ไปตามเลขใหม่ 4 หลัก โดยคงรหัสผ่านเดิม ครูกด **คืนรหัสผ่านเริ่มต้น** แยกต่างหากได้หากต้องการใช้ `RT-เลขใหม่`

Edge Function ตรวจสิทธิ์ครูเจ้าของรายชื่อและข้อมูลเดิมจากฟอร์ม ปฏิเสธเลขซ้ำและฟอร์มที่ล้าสมัย และใช้ lease ฝั่ง server ป้องกันการแก้ชื่อผู้ใช้พร้อมกัน ถ้าบันทึกโปรไฟล์ไม่ได้หลังเปลี่ยน Auth จะคืนชื่อผู้ใช้เดิม โดยไม่เปลี่ยนรหัสผ่าน RPC ผลฝึกยอมให้ครูเขียนเฉพาะข้อสังเกตของรอบที่มีอยู่แล้ว ห้ามสร้างรอบหรือเปลี่ยนข้อมูลแบบฝึก

## ชั้นเรียนและตัวกรองรายงาน

การเพิ่มและแก้ไขผู้เรียนใช้ชุดตัวเลือกชั้นเดียวกัน: ป.1, ป.2, ป.3, ป.4, ป.5 และ ป.6 หน้ารายงานเลือก **กรองชั้นเรียน** ก่อนเลือก **ผู้เรียนที่ต้องการดูรายงาน** ได้ เปลี่ยนชั้นแล้วรายชื่อจะแสดงเฉพาะผู้เรียนที่ตรงกับชั้นนั้น และล้างรายงานเดิมถ้าคนที่เลือกไม่ได้อยู่ในชั้นใหม่

ข้อมูลชั้นเดิม เช่น ป.1/1 ยังอยู่ในบัญชีและค้นผ่านตัวกรอง ป.1 ได้ การบันทึกแก้ไขครั้งถัดไปจะใช้ค่าชั้นจากชุดตัวเลือก โดยไม่เปลี่ยนบัญชีหรือผลฝึกเดิม
